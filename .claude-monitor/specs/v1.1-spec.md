# Claude Session Monitor TUI — v1.1 Spec (UX Redesign)

> Lead/PM: UX Redesign based on v1.0 user feedback
> Version: v1.1
> Date: 2026-04-14
> Previous: v1-spec.md

---

## 0. Feedback from v1.0

From the v1.0 screenshot, three core UX problems:

### Problem 1: Sessions are indistinguishable
All sessions show "Tmp" as project name. No way to tell WHAT each session is doing.

**Root cause:** The `Project` column only shows the project directory name. Multiple sessions in the same project are indistinguishable.

**Solution:** Extract the **first user message** from each session's JSONL as a "Session Topic" — this is the initial prompt that defines what the session does. Show a truncated version in the table as the primary identifier.

### Problem 2: Dashboard table information is sparse
Only PID, Project, Kind, Uptime, Agents columns. Missing: token usage, message count, session topic, git branch, file size.

**Solution:** Richer columns with the most useful information visible at a glance.

### Problem 3: Subagent information is unclear
- PID ↔ Agent Type relationship is confusing — user wants to see a **session's purpose** first, then drill into its subagents
- Description is truncated (ellipsis)
- No token usage, model info, tool call count per agent

**Solution:** Hierarchical view — session shows its mission/topic, expanding into a detailed subagent list with full context.

## 1. New Data Extraction

### 1.1 Session Topic (NEW)
Extract from the **first user message** in `{sessionId}.jsonl`:
```go
// Grep for first line with "type":"user", parse message.content
// If content is a string, use it directly
// If content is an array, join text blocks
// Truncate to 60 chars for table, full text for detail view
```

### 1.2 Git Branch (NEW)
Available in user message JSONL entries:
```json
{ "type": "user", ..., "gitBranch": "main" }
```

### 1.3 Message Count (NEW)
Count lines with `"type":"user"` in the session JSONL = number of user turns.

### 1.4 Session Token Usage (NEW)
Sum all `message.usage.input_tokens` + `message.usage.output_tokens` across the session JSONL.

### 1.5 Last User Message (NEW)
The **last** user message = what the session is currently working on (may differ from first message / session topic).

## 3. New Data Parsers Needed

### 3.1 `ParseSessionTopic(jsonlPath string) string`
Read the **first** line matching `"type":"user"` from the JSONL file.
Extract `message.content` (string or array of text blocks).
Return first 120 chars as topic.

### 3.2 `ParseGitBranch(jsonlPath string) string`
Read the **first** line matching `"type":"user"` and extract `gitBranch` field.

### 3.3 `ParseMessageCount(jsonlPath string) int`
Count lines matching `"type":"user"` — use grep-like byte scanning, don't parse full JSON.

### 3.4 `ParseSessionTokens(jsonlPath string) TokenUsage`
Sum all `message.usage` across the session JSONL.
For large files (>1MB), use chunked reading.

### 3.5 `ParseAgentModel(jsonlPath string) string`
Read **first** assistant message from agent JSONL, extract `message.model`.
Return short name mapping:
- `claude-sonnet-4-*` → `sonnet`
- `claude-haiku-4-5-*` → `haiku`
- `claude-opus-4-*` → `opus`

### 3.6 `ParseAgentToolCalls(jsonlPath string) map[string]int`
Count tool calls by name from agent JSONL entries with `type: "tool_use"`.

### 3.7 `ParseAgentFinalOutput(jsonlPath string) string`
Read the **last** assistant text message from agent JSONL — the agent's final result.
Return last 200 chars.

## 4. Updated Data Types

```go
type Session struct {
    PID           int
    SessionID     string
    CWD           string
    ProjectName   string    // resolved from homunculus or last path segment
    Topic         string    // first user message (truncated)
    TopicFull     string    // first user message (full)
    LastMessage   string    // last user message (truncated)
    GitBranch     string
    Kind          string
    StartedAt     time.Time
    Uptime        string
    IsAlive       bool
    MessageCount  int
    Tokens        TokenUsage
    Agents        []Agent
    Tasks         []Task
    JSONLPath     string
    JSONLSize     int64
}

type Agent struct {
    ID            string
    AgentType     string
    Description   string    // FULL description, never truncated in data layer
    Status        AgentStatus
    LastActiveTime time.Time
    Elapsed       string
    Model         string    // short: "sonnet", "haiku", "opus"
    ModelFull     string    // full: "claude-haiku-4-5-20251001"
    Tokens        TokenUsage
    ToolCalls     map[string]int  // tool name → call count
    ToolCallTotal int
    FinalOutput   string    // last 200 chars of agent's result
    MetaPath      string
    JSONLPath     string
}

type TokenUsage struct {
    InputTokens           int64
    OutputTokens          int64
    CacheCreationTokens   int64
    CacheReadTokens       int64
    Total                 int64
    TotalFormatted        string  // "245K", "29.4M"
}
```

## 5. Implementation Priority

These changes are ordered by impact:

1. **Session Topic extraction** — biggest UX win, makes sessions distinguishable
2. **Token columns** — adds critical missing information  
3. **Model column for agents** — clarifies which model each agent uses
4. **Tool call summary** — shows what agents actually did
5. **Remove Kind column** — declutter
6. **Full description** — stop truncating agent descriptions
7. **Agent final output** — show what the agent concluded
8. **Git branch** — useful context

## 6. Performance Notes

- `ParseSessionTopic`: Only read first ~50 lines of JSONL (seek to find first user message quickly)
- `ParseSessionTokens`: For files > 1MB, this is expensive. Cache result and only re-parse if mtime changed.
- `ParseMessageCount`: Use `bytes.Count([]byte(`"type":"user"`))` on raw bytes, don't JSON-parse each line
- Token formatting: `FormatTokenCount(n int64) string` → `"245K"`, `"29.4M"`, `"1.2B"`
- Cache session topic/branch/message count — they rarely change during a session

### Screenshot Method

Use `vhs` (already installed at `/opt/homebrew/bin/vhs`) to capture terminal screenshots:

```bash
# Create a .tape file for VHS
cat > demo.tape << 'EOF'
Output demo.gif
Set Width 1200
Set Height 800
Set FontSize 14
Type "cd /path/to/project && ./csm"
Enter
Sleep 5s
Screenshot screenshot.png
EOF

vhs demo.tape
```

Alternative: `termshot` (can be installed via `brew install termshot`):
```bash
termshot -- ./csm
# Produces screenshot.png
```

Or simple macOS screenshot after launching:
```bash
./csm &
sleep 2
screencapture -l $(osascript -e 'tell app "Terminal" to id of window 1') screenshot.png
```
